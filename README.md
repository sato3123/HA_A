# ホームパネル（Fire HD 8 / iPad 用 Home Assistant 操作アプリ）

Proxmox 上の Home Assistant OS（HAOS）を操作する、Fire HD 8 向けの Android アプリと、iPad 向けの Web アプリです。

## できること

| 機能 | 内容 |
|---|---|
| 時計と天気 | 画面上部に大きな時計・日付・現在の天気・今日の最高/最低気温・数日分の予報 |
| 機器操作 | 種類ごとの専用ボタン（下表）。状態はリアルタイムに反映 |
| 設定画面 | 項目ごとのメニュー（ホーム画面の表示／部屋と機器／温度計／音声と AI／スクリーンセーバー／カレンダー／ECHONET Lite／外出先からの接続／アカウント／更新・設定の保存）に分かれている |
| 表示する機器の選択 | ⚙ 設定 → 部屋と機器 → 表示する機器 で、名前検索しながらチェック |
| 音声操作 | マイクボタン、または呼びかけ（ウェイクワード）で話しかける |
| AI への質問 | 「〇〇の営業時間を教えて」などを AI が答えて読み上げ。5分以内なら会話の続きも可 |
| 使い方 | トップの「？ 使い方」でいつでも確認。初回は自動で表示 |
| 自動アップデート | 新しいバージョンが出ると「更新する」ボタンが表示される |
| iPad 版 | Proxmox のコンテナ（192.168.1.46）から配信する Web アプリ。Safari の「ホーム画面に追加」で使う（5章） |
| 配色 | ⚙ 設定 → ホーム画面の表示 → 配色 で11種類から選択（暗め・明るい配色もあり） |
| 部屋ごとの表示 | Home Assistant のエリアごとに見出しを付けて表示。部屋で絞り込み。アプリだけの部屋の追加・機器の割り当て、▲▼ で部屋の並べ替えも可 |
| カメラ | Home Assistant のカメラを表示（静止画を10秒ごとに更新）。タップで全画面の動画（高画質の HLS 配信。非対応のカメラは MJPEG の簡易表示） |
| 温度計 | SwitchBot 温湿度計などの温度・湿度を表示。タップで温度・湿度の変化のグラフ（24時間／3日／7日）。名前は部屋の名前などに変更可 |
| スケジュール | 「平日の7:00にエアコンを暖房にする」のような時刻・曜日での自動実行 |
| オートメーション | 「人感センサーが反応したら照明をつける」「日の入りにカーテンを閉める」など、きっかけでの自動実行 |
| アカウント | 普段は管理者以外のユーザー、自動化の編集だけ管理者ログインを追加して使い分け |
| タイマー | 複数のタイマーを同時に設定。ホーム画面に残り時間、時間になるとアラーム。音声（「5分のタイマー」）でも可 |
| スクリーンセーバー | 操作していないときに Google フォトの共有アルバムの写真と時計を表示 |
| 音声の診断 | 設定画面のマイクテストと動作ログで、呼びかけに反応しない原因を確認 |
| 文字入力 | 音声と同じく命令・質問ができ、回答は読み上げ |
| 外出先から利用 | Home Assistant Cloud（Nabu Casa）経由で自動接続。家に戻ると自動でローカルに戻る |
| ログインは1回 | 初回だけ家の中でログイン。パスワードは保存しない |

### 機器ごとの操作

| 種類 | 一覧のタイル | タップで開く詳細パネル |
|---|---|---|
| エアコン | 設定温度 −/＋、運転モード（冷房・暖房・除湿・送風・自動・停止） | 室温・湿度、風量、風向き、プリセット |
| 照明 | オン/オフ、明るさ | 色温度、色（8色） |
| ファン | オン/オフ、風量 | モード、首振り |
| カーテン・シャッター | 開・停止・閉、開き具合 | 同左 |
| スイッチ・シーン・スクリプト | タップで切り替え/実行 | — |
| カメラ | 静止画（10秒ごとに更新） | 全画面の動画 |

※ ボタンは機器が対応している機能だけ表示されます。

## 1. Home Assistant 側の準備

### 1-1. 基本
1. 「設定 → ユーザー」で、タブレット用の管理者ではないユーザーを作ります。
2. HAOS の VM の IP アドレスをルーターで固定します。
3. 天気：「設定 → デバイスとサービス」に天気の連携（標準の Met.no など）があることを確認します。

### 1-2. AI に答えさせる（営業時間などの質問）
1. 「設定 → デバイスとサービス → 統合を追加」で **OpenAI** を追加し、API キーを入力します。
2. 追加した OpenAI の会話エージェントの設定で、次を選びます。
   - モデル：gpt-4o 以降
   - **Enable web search** をオン（営業時間などのWeb検索に必要）
   - **Include home location** をオン（近くのお店を探しやすくなる）
   - **Control Home Assistant** を Assist に（AI からも機器を操作できるようにする場合）
3. 「設定 → 音声アシスタント」で日本語のアシスタントを開き、会話エージェントに OpenAI を選びます。
4. 同じ画面の **「コマンドをローカルで優先処理する」** をオンにします。照明・エアコンなどの命令は今までどおり速く家の中で処理され、それ以外の質問だけ AI に送られます。

※ Google Gemini 連携の Google 検索機能は「機器を操作しない」設定のときしか使えないため、機器操作と一緒に使うなら OpenAI が向いています。
※ OpenAI の API 利用料がかかります。

### 1-3. 呼びかけ（ウェイクワード）
1. アドオンで **openWakeWord** を入れて起動します。
2. 「設定 → 音声アシスタント」でアシスタントを開き、「ウェイクワード」に openWakeWord と言葉（例：ok_nabu）を選びます。
3. アプリの ⚙ 設定 → 「呼びかけで反応する」をオンにします。

**「OK Google」にしたい場合**
- Fire OS では Google アシスタント自体は動きません。代わりに openWakeWord の **カスタムモデル** を使います。
- 作り方は公式手順のとおりです：https://www.home-assistant.io/voice_control/create_wake_word/ （ブラウザ上で言葉を入力して学習 → できたファイルを `/share/openwakeword` に置く → ウェイクワードの一覧から選ぶ）
- 注意：近くに Google のスマホや Nest スピーカーがあると、それらも同時に反応します。気になる場合は別の言葉をおすすめします。
- Fire の Alexa ハンズフリーがオンだとマイクを取り合うことがあります。「設定 → Alexa → ハンズフリーモード」をオフにしてください。

### 1-4. 外出先から使う（Home Assistant Cloud）
1. 「設定 → Home Assistant Cloud」で Nabu Casa のアカウントにサインインします（有料）。
2. 「リモートコントロール」をオンにし、表示される URL（`https://xxxx.ui.nabu.casa`）を控えます。
3. アプリの ⚙ 設定 →「外出先からの接続」にその URL を入力して保存します。

動きは次のとおりです。
- 家のWi-Fiでサーバーに届くとき：ローカル接続（`http://IP:8123`）
- それ以外：Cloud 経由で接続（画面左上に「外出先（Cloud）」と表示）
- 外出先接続中も1分ごとに確認し、家に戻ったらローカルへ切り替えます。
- 外出先では通信量を抑えるため、呼びかけ待ち受けは止めます（マイクボタンは使えます）。
- アプリが接続するのは「家の中のアドレス」と「登録したリモートURL」だけです。
- 同じ Cloud で Google アシスタント連携もできます（「音声アシスタント → 公開」で Google に出す機器を選び、Google Home アプリで「Home Assistant Cloud by NABU CASA」をリンク）。

## 2. 自動アップデートの準備（最初に1回だけ）

`main` ブランチに変更が入ると、GitHub Actions が自動でビルドして「リリース」を作ります。
アプリ（Android 版・iPad 版とも）は、この最新リリースを見て自分で更新します。

1. **リポジトリを公開にする**：GitHub のリポジトリ画面 →「Settings」→ 一番下の「Danger Zone」→「Change visibility」→「Public」。
   - 非公開のままだと、タブレットから更新ファイルをダウンロードできません。
   - コードにパスワードなどの秘密情報は含まれていません。
2. **署名鍵を登録する（Android 版用）**：「Settings → Secrets and variables → Actions → New repository secret」で、次の2つを登録します。
   - `KEYSTORE_BASE64`：署名鍵ファイルを base64 にした文字列
   - `KEYSTORE_PASSWORD`：署名鍵のパスワード
   - Android は、毎回同じ鍵で署名したアプリでないと上書き更新できません。鍵ファイルは大切に保管してください（なくすと、アプリを入れ直す必要があります）。
3. 登録後に `main` へ変更が入ると、Android 版の APK もリリースに載るようになります。

## 3. Fire HD 8 へのインストール

**APK の入手**：リポジトリの「Releases」から最新の `HomePanel-1.0.xx.apk` をダウンロードします。

**初回のインストール**
1. Fire の「設定 → セキュリティとプライバシー → 提供元不明のアプリ」で、Silk ブラウザ（またはファイルアプリ）を許可します。
2. Silk で Releases ページを開いて APK をダウンロードし、開いてインストールします。
   - これまでの `app-debug.apk`（署名鍵が違うもの）が入っている場合は、先にアンインストールしてください（最初の1回だけ）。

**2回目以降の更新**
- 新しいバージョンが出ると、ホーム画面の上に「更新する」ボタンが出ます。押すとダウンロードしてインストール画面が開きます。
- 初回だけ「このアプリからのインストールを許可」の画面が出るので、オンにして戻り、もう一度「更新する」を押します。
- ⚙ 設定 または ？ 使い方 の「更新を確認」でも確認できます。

**ADB で入れる場合**：開発者オプションで ADB を有効にし、`adb install -r HomePanel-1.0.xx.apk` を実行します。

## 4. Fire HD 8 の初回起動
1. 家の中で URL（例：`192.168.1.10` → `http://192.168.1.10:8123` に補完）、ユーザー名、パスワードを入力します。
2. マイクの権限を許可します。
3. 使い方の画面が自動で開きます（あとからトップの「？ 使い方」でいつでも見られます）。
4. ⚙ 設定で、外出先用 URL、呼びかけ、使うアシスタント、表示する機器を設定します。

## 5. iPad 版（Web アプリ）

Apple の開発者登録や Mac は不要です。Proxmox に小さなコンテナ（LXC）を1つ作り、そこから iPad 版を配信します。

```
iPad ──https──▶ 192.168.1.46（LXC：Caddy）──▶ 192.168.1.45:8123（Home Assistant）
                  ├ /homepanel/ … iPad 版の画面
                  └ それ以外   … Home Assistant へ中継（ログイン・API・音声）
```

- iPad からは 192.168.1.46 の https のサイト1つに見えるので、**Home Assistant Cloud なしで、家の中から音声入力が使えます**。
- Home Assistant の設定ファイルを変更する必要はありません。
- コンテナが GitHub の最新版を5分おきに確認して、自動で更新します。
- 家の外からは使えません（家の中専用）。

### 5-1. コンテナを作る（Proxmox で1回だけ）
Proxmox の管理画面で、ノード（例：pve）→「シェル」を開き、次の1行を貼り付けて実行します。

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sato3123/HA_A/main/server/create-lxc.sh)
```

- コンテナ番号 146、IP 192.168.1.46、ルーター 192.168.1.1、ディスクは local-lvm で作ります。
- 違う場合は先頭に指定します。例：`GATEWAY=192.168.1.254 CTID=150 STORAGE=local-zfs bash <(curl ...)`
- 最後に「セットアップが終わりました」と表示されれば完了です。

すでにコンテナがある場合は、その中（Debian 12 / root）で次を実行しても同じです。

```bash
curl -fsSL https://raw.githubusercontent.com/sato3123/HA_A/main/server/setup.sh | HA_IP=192.168.1.45 SELF_IP=192.168.1.46 bash
```

### 5-2. iPad に証明書を入れる（1回だけ）
家の中専用の https なので、iPad にこのサーバーの証明書を信頼させます。

1. iPad の **Safari** で `http://192.168.1.46/ca.crt` を開き、「許可」→ プロファイルをダウンロードします。
2. 「設定」アプリの上部に出る「プロファイルがダウンロードされました」→「インストール」。
3. 「設定 → 一般 → 情報 → **証明書信頼設定**」で「Caddy Local Authority …」を**オン**にします。

### 5-3. iPad で開く
1. Safari で `https://192.168.1.46/` を開きます（自動で `/homepanel/` に移動します）。
2. 「Home Assistant でログイン」→ いつもの Home Assistant のログイン画面でログインします（最初の1回だけ）。
3. 共有ボタン（□↑）→「ホーム画面に追加」で、ホーム画面にアイコンができます。
   - ホーム画面のアイコンから開いた後に、もう一度だけログインが必要です（Safari とログイン情報が別のため）。
4. マイクボタンを初めて押したときに、マイクを「許可」にします。

### 5-4. iPad 版でできること・違い
- Android 版と同じく、時計と天気、機器ごとの操作、部屋ごとの表示、配色、音声操作・AI への質問、自動化、使い方画面があります。
- 呼びかけ（ウェイクワード）は画面を表示している間だけ動きます。「設定 → 画面表示と明るさ → 自動ロック」を「しない」にすると、常時表示のパネルとして使えます。

### 5-5. 更新
- コンテナが5分おきに自動で更新します。画面上部に「更新する」が出たら押すと、入れ替わり次第、自動で読み込み直します。
- すぐ更新したいとき：Proxmox でコンテナのコンソールを開き `homepanel-update` を実行します。

### 5-6. うまくいかないとき
- **「この接続ではプライバシーが保護されません」**：5-2 の証明書が入っていないか、「証明書信頼設定」がオフです。
- **ログイン後に「400: Bad Request」**：Home Assistant の `configuration.yaml` に次を追加して再起動してください（通常は不要です）。
  ```yaml
  http:
    use_x_forwarded_for: true
    trusted_proxies:
      - 192.168.1.46
  ```
- **画面が出ない**：コンテナのコンソールで `systemctl status caddy` を確認します。
- コンテナの IP や Home Assistant の IP を変えたときは、5-1 のセットアップ用コマンド（2つ目）を新しい IP で実行し直します。

### 5-7. （別の方法）Home Assistant の中に置く
コンテナを作らずに、Home Assistant の `/config/www` に置く方法もあります。この場合、音声入力には Home Assistant Cloud の https のアドレスが必要です。

```yaml
shell_command:
  update_homepanel: >-
    python3 -c "import io,json,urllib.request as u,zipfile;r=json.load(u.urlopen('https://api.github.com/repos/sato3123/HA_A/releases/latest'));a=[x['browser_download_url'] for x in r['assets'] if x['name']=='homepanel-web.zip'][0];zipfile.ZipFile(io.BytesIO(u.urlopen(a).read())).extractall('/config/www/homepanel')"
```
`configuration.yaml` に追記 → 再起動 →「開発者ツール → アクション」で `shell_command.update_homepanel` を実行 → `https://xxxx.ui.nabu.casa/local/homepanel/index.html` を開きます。

## 6. スケジュール・オートメーションとアカウント

### 6-1. しくみ
- トップの「⏰ 自動化」から作ります。作ったものは **Home Assistant の自動化として保存** されるので、タブレットや iPad の電源が切れていても Home Assistant が実行します。
- Home Assistant の「設定 → オートメーションとシーン」にも同じものが表示されます（説明欄に「ホームパネルで作成」と入ります）。
- アプリで作ったもの（ID が `hp_` で始まる）はアプリで編集できます。Home Assistant の画面で作った自動化は、アプリではオン/オフと「今すぐ実行」だけできます。

### 6-2. 作れる内容
- **スケジュール**：時刻＋曜日（毎日・平日・土日・個別）→ 実行すること
- **オートメーション**：きっかけ（時刻／機器の状態／日の出／日の入り＋前後の分）＋曜日＋時間帯（任意）→ 実行すること
- **実行すること**（複数可）：照明（つける・明るさを指定・消す）、エアコン（運転モード・温度・停止）、カーテン（開ける・閉める・開き具合）、スイッチ・ファン（オン/オフ）、シーン・スクリプトの実行
- きっかけに使える機器：人感・ドアなどのセンサー、人（帰宅・外出）、照明、スイッチ、カーテン、エアコン、鍵 など

### 6-3. 管理者とその他のユーザー
Home Assistant では、自動化の作成・編集は管理者ユーザーだけに許可されています。そこで、次のように使い分けられます。
- **普段使い**：アプリへのログインは管理者以外のユーザー（おすすめ）。機器の操作・音声・オン/オフ・今すぐ実行はこれで使えます。
- **自動化の編集**：⚙ 設定 →「アカウント」→「管理者ログインを追加」で管理者ユーザーでもログインします。編集のときだけ管理者の権限を使います。
  - Android 版：その場でユーザー名とパスワードを入力します。
  - iPad 版：Home Assistant のログイン画面が開くので、管理者のユーザー名でログインします。
- 使い終わったら「管理者ログインを解除」できます。普段使いのユーザーが管理者なら、追加しなくてもそのまま編集できます。

### 6-4. 部屋
- Home Assistant の「設定 → エリア」で設定したエリアが、そのまま部屋になります（機器のエリアが未設定なら、その機器が属するデバイスのエリアを使います）。
- ⚙ 設定 →「部屋」でアプリだけの部屋を追加でき、「表示する機器」の各機器の「🏠」で部屋を変えられます（この割り当ては端末ごとに保存され、Home Assistant には書き込みません）。

## 7. タイマー・スクリーンセーバー・カレンダー

### 7-1. タイマー
- トップの「⏱ タイマー」から設定します（1〜60分のボタン、または分・秒を指定。名前も付けられます）。
- 音声：「5分のタイマー」「パスタの3分タイマー」「1時間半のタイマー」「タイマーの残りは？」「タイマーを止めて」。
  この言葉はアプリが聞き取った時点で処理し、AI には送りません。
- タイマーはその端末の中で動きます（Fire HD 8 と iPad で別々）。

### 7-2. スクリーンセーバー（Google フォト）
1. スマホの Google フォトで表示したいアルバムを開き、「共有」→「リンクを作成」してリンクをコピーします。
2. アプリの ⚙ 設定 →「スクリーンセーバー」でオンにし、リンクを貼り付けて「保存して読み込む」。
3. 「今すぐ表示して試す」で確認できます。

注意：Google フォトの公式の仕組み（Library API）は 2025年3月31日から、アプリが既存のアルバムを読めなくなりました。そのため、共有リンクのページから写真を取り出す非公式の方法を使っています。Google 側の変更で使えなくなる可能性があります。
- Android 版：タブレットが直接 Google フォトから読み込みます。
- iPad 版：Proxmox のコンテナ（192.168.1.46）が代わりに読み込みます。**コンテナを以前に作った場合は、5-1 のセットアップ用コマンド（2つ目）をもう一度実行**してください（写真の機能が追加されます）。

### 7-3. TimeTree との連携について（確認結果）
- TimeTree の公式 API（Connect App）は **2023年12月22日に終了** しており、公式の連携方法はありません。
- 非公式の方法として、Home Assistant 用の個人製の連携（HACS のカスタムリポジトリ）があり、TimeTree のメールアドレスとパスワードでログインして、カレンダーを Home Assistant の calendar として取り込めます。非公式のため、TimeTree 側の変更で使えなくなる可能性や、パスワードを Home Assistant に保存する点に注意が必要です。
- Home Assistant に取り込めれば、このアプリで「今日の予定」を表示することはできます（必要ならご相談ください）。

## ファイル構成
- `NetworkGuard.kt`：ローカル/Cloud の自動切り替え、接続先を限定する DNS
- `Auth.kt`：ログイン（login_flow → token）と、暗号化したトークンの保存
- `HaClient.kt`：WebSocket API（状態の購読、サービス呼び出し）
- `VoiceAssistant.kt`：呼びかけ検知 → 音声認識 → 会話（AI） → 読み上げのパイプライン実行
- `MainViewModel.kt`：接続ループ、天気予報、待ち受けループ、設定
- `Ui.kt`：ログイン・ホーム（時計/天気/音声）画面
- `Controls.kt`：機器の種類ごとのタイルと詳細パネル
- `Settings.kt`：設定画面
- `Help.kt`：使い方画面と更新の案内
- `Themes.kt`：配色パターン（iPad 版の style.css も同じ色）
- `Rooms.kt`：部屋（エリア）の判定とグループ分け
- `Rules.kt`：スケジュール・オートメーションと Home Assistant の自動化設定の変換
- `AutomationScreen.kt`：自動化の一覧と編集画面
- `Timers.kt`：タイマーと音声でのタイマー命令の読み取り
- `Overlays.kt`：タイマー表示・アラーム・スクリーンセーバー・マイクテスト
- `Photos.kt`：Google フォトの共有アルバムから写真を取り出す
- `Updater.kt`：GitHub のリリースを確認してダウンロード・インストール
- `server/`：iPad 版を配信する LXC コンテナの作成（create-lxc.sh）とセットアップ（setup.sh）
- `web/`：iPad 版（Web アプリ）。`app.js` が本体、`index.html` はバージョン付きで本体を読み込むだけ

## 注意
- ログインを何度も失敗すると、HA の設定によってはタブレットの IP がブロックされます（`ip_bans.yaml`）。
- 呼びかけ待ち受け中は、音声を家のサーバーへ送り続けます（1時間あたり約115MB、家の中のみ）。
- 更新の確認では GitHub（api.github.com とダウンロード用サーバー）にだけ接続します。
